# Соответствие техническому заданию

Каждое требование ТЗ — где реализовано и как проверить в работающем проекте.
Проверка ведётся от лица вошедшего пользователя, если не указано иное.

## 1. Учёт финансовых операций

| Требование ТЗ | Реализация | Как проверить |
| --- | --- | --- |
| Ручное добавление доходов и расходов | `TransactionCreateView`, форма `TransactionForm` | «Добавить операцию» в шапке |
| Обязательные поля: сумма, дата, тип, категория | Модель `Transaction` | Форма не принимается без них |
| Описание операции | `Transaction.description` | Необязательное поле формы |
| Минимум 3 категории | `DEFAULT_CATEGORIES` — 7 штук выдаются при регистрации | Зарегистрировать нового пользователя: категории уже есть |
| Управление категориями | `CategoryListView` и формы создания, изменения, удаления | Раздел «Категории» |

Тип операции берётся из справочника `OperationType`, у категорий он тоже есть:
доход нельзя записать в категорию расходов. Проверяется на уровне модели,
поэтому правило действует и в вебе, и в боте, и в админке.

## 2. Аналитика и отчёты

| Требование ТЗ | Реализация | Как проверить |
| --- | --- | --- |
| Графики доходов и расходов по времени | `charts.timeline_chart`, `charts.cumulative_chart` | Раздел «Аналитика» |
| Диаграмма расходов по категориям | `charts.category_chart` — кольцевая | Там же, блок «Структура расходов» |
| Фильтры: день, неделя, месяц, год | `periods.py`, `TransactionFilterForm` | Список периодов в фильтре, плюс произвольный диапазон |
| Общие доходы, расходы, баланс | `analytics.totals` | Карточки вверху «Аналитики» и «Операций» |
| Отчёты по категориям и периодам | `analytics.expenses_by_category`, таблица долей | Блок «Расходы по категориям» |
| Выявление аномалий | `analytics.find_anomalies` | Совет «Резкий рост расходов» при скачке трат |
| Рекомендации на основе трат | `analytics.build_advice` | Блок советов над графиками |
| Предупреждение о превышении лимита | `analytics.limit_usage`, поле `Category.monthly_limit` | Задать лимит категории и превысить его |

Аномалией считается рост расходов по категории **в 1.5 раза** относительно
среднего за три предыдущих периода такой же длины **и минимум на 500 ₽** —
второе условие отсекает скачки на мелких суммах.

Лимит в ТЗ допускается «по категории или общему бюджету» — сделан по категории.
Он всегда считается за текущий месяц и не зависит от выбранного фильтра:
сравнивать месячный лимит с годовой суммой бессмысленно.

## 3. Telegram-бот

| Требование ТЗ | Реализация | Как проверить |
| --- | --- | --- |
| Команда `/today` | `handlers.cmd_today` | Отправить боту `/today` |
| Команда `/week` | `handlers.cmd_week` | `/week` |
| Команда `/category food` | `handlers.cmd_category`, поиск без учёта регистра | `/category еда` |
| Краткий ежедневный отчёт | `reports.daily_digest` | Команда `senddigest` или раздел «Обслуживание» |
| Кнопка «Подробнее» | `keyboards.report_actions` | Под любым отчётом бота |
| Кнопка «Сравнить с прошлой неделей» | `reports.compare_periods` | Кнопка подстраивается под период отчёта |
| Кнопка «Добавить трату» | Сценарий `AddOperation` | Кнопка под отчётом или `/add` |
| Дата операции | Шаг сценария: кнопки, слова «вчера» или число | В боте: `/add` → сумма → категория → дата |
| Связь Telegram ID с пользователем | `Profile.telegram_id`, привязка по коду | Профиль → код → `/start КОД` |
| Уведомления по расписанию (опционально) | Команда `senddigest` под cron | README, раздел «Уведомления по расписанию» |
| Уведомления о лимитах (опционально) | `reports.limit_warnings` | Приходят вместе со сводкой, не чаще раза в месяц |

Сверх ТЗ: `/month`, `/year`, `/income`, `/advice`, `/unlink`, создание категории
прямо в чате и постраничный список категорий.

## 5. База данных

| Требование ТЗ | Реализация |
| --- | --- |
| Хранение пользователей и их финансовых данных | `User` (Django) + `Profile`, `Category`, `Transaction` |
| Таблица операций | `finance_transaction` |
| Таблица категорий | `finance_category` |
| Таблица советов | **Не заводилась намеренно** — см. ниже |
| Таблица аномалий | **Не заводилась намеренно** — см. ниже |
| История уведомлений | `finance_notificationlog` |
| Связь Telegram ID и пользователя | `finance_profile.telegram_id` |
| SQLite на этапе MVP | `db.sqlite3` |

**Почему советы и аномалии не хранятся.** И то, и другое — функция от текущих
операций, а не самостоятельная сущность. Сохранённый совет «вы тратите на еду
больше обычного» назавтра протухнет и начнёт врать, а пересчитать его заново
стоит один запрос. Поэтому они вычисляются на лету в `analytics.py`.
Хранится то, у чего есть собственная жизнь: история отправленных уведомлений —
без неё бот повторял бы одно и то же предупреждение каждый вечер.

## Критерии успешного выполнения

| Критерий ТЗ | Чем подтверждается |
| --- | --- |
| Пользователь регистрируется, добавляет операции, смотрит историю | Тесты `SignUpTests`, `TransactionFlowTests` |
| Система строит корректные графики и считает аналитику | `AnalyticsTests`, `WebComparisonTests`, `OpenPeriodChartTests` |
| Бот стабильно отвечает и отправляет статистику | `BotServiceTests`, `BotKeyboardTests`, `DailyDigestTests` |
| Данные хранятся и обрабатываются безопасно | `AccessTests`: чужие данные недоступны даже по прямой ссылке |
| Интерфейс адаптивный и понятный | Сетка Bootstrap, подсказки на всех действиях |

Запуск проверки: `python manage.py test finance` — 149 тестов.

## Что не делалось

ИИ, экспорт в PDF и Excel, голосовой ввод трат. Это не упущение, а граница MVP до которой мы дошли.
