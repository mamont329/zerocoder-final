# Сценарий демонстрации

Порядок, в котором проект показывает всё заявленное в ТЗ примерно за пятнадцать
минут. Каждый шаг проверяется глазами, ничего не нужно смотреть в коде.

## Подготовка

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install -r requirements.txt

copy .env.example .env            # заполнить SECRET_KEY
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Сайт: http://127.0.0.1:8000/

Для бота нужен токен от [@BotFather](https://t.me/BotFather) в `.env`
(`TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`), затем в отдельном окне:

```bash
python manage.py setupbot   # имя, описание, меню команд и аватарка
python manage.py runbot
```

Проект работает и без бота — веб-часть от него не зависит.

## 1. Регистрация и стартовое состояние

1. Открыть `/accounts/signup/`, завести пользователя.
2. После регистрации сразу открывается сводка — вход выполнен автоматически.
3. Зайти в «Категории»: там уже 7 категорий, пять расходных и две доходных.

**Что показано:** регистрация, авторизация, требование ТЗ «минимум 3 категории».

## 2. Учёт операций

1. «Добавить операцию» → расход, сумма, категория, описание.
2. Переключить тип на «Доход» — список категорий перестроится: «Еда» исчезнет,
   останутся «Зарплата» и «Подработка».
3. Добавить несколько операций разными датами, в том числе за прошлый месяц.
4. Открыть «Операции»: история, фильтры, итоги по выборке, пагинация по 20.

**Что показано:** обязательные поля, описание, связь типа операции с типом
категории, история с фильтрами.

## 3. Управление категориями

1. Открыть «Еду» на редактирование и задать месячный лимит — например 8000 ₽.
2. Попробовать создать новую категорию с именем «еда» — система не даст:
   имена сравниваются без учёта регистра.
3. Попробовать удалить категорию, в которой есть операции — тоже не даст
   и объяснит, почему.

**Что показано:** CRUD категорий, защита истории операций.

## 4. Аналитика

Раздел «Аналитика», период «Текущий месяц»:

1. Карточки: доходы, расходы, баланс.
2. Сравнение с предыдущим периодом — рост расходов красным, рост доходов зелёным.
3. Советы: превышение лимита, резкий рост по категории, доля основной статьи.
4. График динамики по дням, график нарастающего итога, кольцевая диаграмма
   расходов и таблица долей.
5. Полоски лимитов по категориям.

Переключить период на «Год» — график перестроится по месяцам, сравнение
пойдёт год к году. Выбрать «Произвольный период» — появятся поля дат.

**Что показано:** графики по времени, диаграмма по категориям, фильтры периодов,
итоги, отчёты по категориям, аномалии, советы, лимиты.

## 5. Избранные отчёты

1. Выставить фильтр: период «Текущий месяц», тип «Расход», категория «Еда».
2. Ввести имя «Еда за месяц» → «Сохранить отчёт».
3. Сменить фильтр на что-то другое, затем нажать на сохранённый отчёт —
   фильтры вернутся.

**Что показано:** требование ТЗ «Сохранение избранных отчётов».

## 6. Telegram-бот

1. «Профиль» → скопировать код привязки.
2. В боте отправить `/start КОД` — чат привязан.
3. `/today`, `/week`, `/month` — сводки с кнопками.
4. Кнопка «Подробнее» — советы за тот же период.
5. Кнопка «Сравнить месяцы» — сравнение с прошлым месяцем.
6. Кнопка «Добавить трату» или `🔴 Добавить трату` внизу: сумма → категория →
   дата → описание. Дату можно выбрать кнопкой «Вчера» или ввести вручную.
   Операция появится на сайте.
7. `/category еда` — траты по категории с лимитом и последними операциями.

**Что показано:** команды из ТЗ, интерактивные кнопки, добавление операции
из чата, связь Telegram ID с аккаунтом.

## 7. Уведомления по расписанию

Раздел «Обслуживание» (виден сотрудникам):

1. «Показать текст» — как выглядит ежедневная сводка.
2. «Отправить» — сводка уходит в Telegram.
3. «Отправить» ещё раз — система объяснит, что сегодня уже отправляла.
4. «Отправить повторно» — доставит ещё раз.
5. «Состояние» — когда кому уходили сводки.
6. Таблица истории уведомлений внизу страницы.

В README описан запуск того же самого по расписанию через cron или
«Планировщик заданий» Windows.

**Что показано:** ежедневный отчёт, уведомления о лимитах, защита от повторов,
планировщик.

## 8. Учётные записи (сверх ТЗ)

Раздел «Пользователи»:

1. Создать пользователя — пароль придумывать не нужно, система выдаёт временный
   и показывает его один раз с кнопкой «Копировать».
2. Войти под новым пользователем — сервис потребует задать свой пароль и не
   пустит дальше, пока это не сделано.
3. Вернуться под сотрудником, нажать «Сбросить пароль» — выбрать каналы доставки.
4. «Отключить» пользователя: вход и бот закрываются, данные остаются.

**Что показано:** управление доступом, временные пароли, обязательная смена.

## 9. Изоляция данных

1. Зарегистрировать второго пользователя — у него пустая история и свои категории.
2. Скопировать ссылку на операцию первого пользователя и открыть под вторым —
   вернётся 404, а не чужие данные.

**Что показано:** критерий ТЗ «данные хранятся и обрабатываются безопасно».
