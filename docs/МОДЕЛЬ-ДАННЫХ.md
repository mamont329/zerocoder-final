# Модель данных

Пять собственных таблиц плюс штатный `User` из `django.contrib.auth`.

## Схема связей

```
┌──────────────────────────────┐
│  User  (django.contrib.auth) │  логин, пароль, имя, фамилия, почта,
│                              │  is_active, is_staff
└───┬────────┬────────┬────────┘
    │ 1:1    │ 1:N    │ 1:N
    │        │        │
    │        │        └────────────────────────┐
    │        │                                 │
┌───┴──────────────┐   ┌─────────────────┐  ┌──┴────────────────┐
│  Profile         │   │  Category       │  │  NotificationLog  │
│──────────────────│   │─────────────────│  │───────────────────│
│ middle_name      │   │ name            │  │ kind              │
│ telegram_id      │   │ type            │  │ key               │
│ link_code        │   │ monthly_limit   │  │ sent_at           │
│ daily_report     │   └────┬────────┬───┘  └───────────────────┘
│ must_change_pwd  │      1 │      1 │
└──────────────────┘        │        │
                          N │        │ N
                  ┌─────────┴────┐ ┌─┴──────────────┐
                  │ Transaction  │ │  SavedReport   │
                  │──────────────│ │────────────────│
                  │ type         │ │ name           │
                  │ amount       │ │ period         │
                  │ date         │ │ date_from/to   │
                  │ description  │ │ type           │
                  │ created_at   │ │ created_at     │
                  └──────────────┘ └────────────────┘

Transaction и SavedReport также ссылаются на User напрямую.
```

## Таблицы

### Profile — настройки пользователя

Один к одному с `User`, создаётся сигналом при регистрации.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `user` | OneToOne → User, CASCADE | Владелец |
| `middle_name` | CharField(150) | Отчество — в модели Django его нет |
| `telegram_id` | BigInteger, уникально, может быть пустым | Чат, куда бот шлёт отчёты |
| `link_code` | CharField(12), уникально | Код привязки чата, меняется при отвязке |
| `daily_report` | Boolean | Присылать ли сводку за день |
| `must_change_password` | Boolean | Пароль временный, нужна смена при входе |

### Category — категории доходов и расходов

| Поле | Тип | Назначение |
| --- | --- | --- |
| `user` | FK → User, CASCADE | Категории личные, не общие на сервис |
| `name` | CharField(100) | «Еда», «Зарплата» |
| `type` | CharField + choices | Доход или расход |
| `monthly_limit` | Decimal(12,2), может быть пустым | Лимит трат за месяц |

Ограничение `unique_category_per_user`: у одного человека не может быть двух
категорий с одним именем, у разных — может.

### Transaction — финансовые операции

| Поле | Тип | Назначение |
| --- | --- | --- |
| `user` | FK → User, CASCADE | Владелец операции |
| `type` | CharField + choices | Доход или расход |
| `amount` | Decimal(12,2), минимум 0.01 | Сумма, всегда положительная |
| `date` | Date, по умолчанию сегодня | Когда потрачено — по ней вся аналитика |
| `category` | FK → Category, **PROTECT** | Категория операции |
| `description` | CharField(255), необязательно | Комментарий |
| `created_at` | DateTime, автоматически | Когда запись внесли в систему |

Индекс `transaction_user_date_idx` по паре `(user, date)` — под самый частый
запрос проекта «мои операции за период».

### NotificationLog — история уведомлений

| Поле | Тип | Назначение |
| --- | --- | --- |
| `user` | FK → User, CASCADE | Получатель |
| `kind` | CharField + choices | Сводка за день или предупреждение о лимите |
| `key` | CharField(100) | Ключ события: `2026-08-20`, `limit:3:2026-08` |
| `sent_at` | DateTime, автоматически | Когда отправлено |

Ограничение `unique_notification` по тройке `(user, kind, key)` — именно оно, а
не проверка в коде, гарантирует, что одно и то же не уйдёт дважды даже при
случайном параллельном запуске рассылки.

### SavedReport — избранные отчёты

| Поле | Тип | Назначение |
| --- | --- | --- |
| `user` | FK → User, CASCADE | Владелец |
| `name` | CharField(100) | «Месячный анализ» |
| `period`, `date_from`, `date_to`, `type`, `category` | — | Сохранённый набор фильтров |
| `created_at` | DateTime, автоматически | Когда сохранён |

Ограничение `unique_report_per_user` по паре `(user, name)`.

## Три решения, которые стоит объяснить

**Сумма всегда положительная, направление задаёт `type`.** Хранить расходы
отрицательными числами было бы короче, но тогда любой отчёт превращается в набор
условий «сложи только отрицательные и возьми модуль», а пользователь может
случайно ввести минус у дохода. Сейчас правило простое: сумма положительная,
баланс — доходы минус расходы.

**Две даты у операции.** `date` — когда деньги потрачены, её ставит пользователь
и может указать вчерашний обед. `created_at` — когда запись появилась в базе.
Аналитика и команды бота считают по `date`, `created_at` нужна для сортировки
операций внутри одного дня.

**`user` есть и у операции, и у её категории.** Формально владельца операции
можно вычислить через категорию, но прямое поле даёт единое правило доступа
`filter(user=request.user)` для всех моделей проекта и позволяет построить
индекс `(user, date)`, невозможный при связи через соседнюю таблицу. Цена —
инвариант «категория операции принадлежит её владельцу», который проверяется
в `Transaction.clean()`.

## Удаление данных

| Что удаляем | Что происходит |
| --- | --- |
| Категория без операций | Удаляется |
| Категория с операциями | **Запрещено** (`PROTECT`), система объясняет причину |
| Пользователь | Удаляются его операции, категории, профиль, отчёты и уведомления |

Удаление пользователя выполняется функцией `purge_user`: сначала операции, потом
всё остальное. Прямой `user.delete()` упал бы с `ProtectedError`, потому что
категории уходят каскадом, а их держат операции. Той же функцией пользуется
админка Django.
