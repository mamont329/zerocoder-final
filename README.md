# FinControl

Сервис учёта личных финансов: веб-интерфейс на Django и Telegram-бот.
Позволяет вести доходы и расходы, смотреть аналитику по категориям и периодам,
получать советы и предупреждения о превышении лимитов.

## Стек

- Python 3.13, Django 6.1
- SQLite
- pandas, plotly — аналитика и графики
- aiogram — Telegram-бот
- Bootstrap — вёрстка

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # Linux / macOS

pip install -r requirements.txt

cp .env.example .env            # и заполнить SECRET_KEY
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Сайт: http://127.0.0.1:8000/, админка: http://127.0.0.1:8000/admin/

## Аналитика

Графики строятся на plotly, агрегаты — на pandas. Палитра выбрана так, чтобы
серии различались при дальтонизме: доход — синий, расход — оранжевый
(привычная красно-зелёная пара для этого наименее пригодна). На кольцевой
диаграмме не больше пяти категорий, остальные сворачиваются в «Прочее», а
полный список всегда есть в таблице рядом.

Аномалией считается рост расходов по категории в 1.5 раза и минимум на 500 ₽
относительно среднего за три предыдущих периода той же длины.

## Учётные записи

Пользователи регистрируются сами либо заводятся сотрудником в разделе
«Пользователи». Во втором случае пароль не придумывается: система генерирует
временный, показывает его один раз и отправляет на почту и в Telegram, если они
известны. До первой смены пароля сервис для такого пользователя закрыт —
за этим следит `finance/middleware.py`.

Пользователь может отключить себя сам: данные сохраняются, вход и бот
закрываются. Безвозвратное удаление и возврат доступа — за сотрудниками.
Последний активный сотрудник отключить себя не может, иначе включать учётные
записи будет некому.

Почта не настроена: письма печатаются в консоль сервера. Для боевой работы
в `MAILERS` прописывается SMTP, остальной код не меняется.

## Telegram-бот

Токен от [@BotFather](https://t.me/BotFather) кладётся в `.env`:

```
TELEGRAM_BOT_TOKEN=123456:AA...
TELEGRAM_BOT_USERNAME=имя_бота_без_собаки
```

```bash
python manage.py setupbot   # имя, описания, меню команд и аватарка
python manage.py runbot     # запуск бота
```

Чат привязывается к аккаунту кодом из раздела «Профиль»: `/start ВАШ_КОД`.

Команды: `/today`, `/week`, `/month`, `/year`, `/category еда`, `/add`, `/income`,
`/advice`, `/unlink`, `/help`. Под отчётами — кнопки «Подробнее» и сравнение
с предыдущим периодом такой же длины.

Отчёты бота считаются теми же функциями, что и веб-аналитика: `finance/analytics.py`
ничего не знает про HTTP, поэтому цифры на сайте и в чате не расходятся.

## Уведомления по расписанию

Сводка за день и предупреждения о лимитах уходят в Telegram тем, у кого включён
«Ежедневный отчёт» в профиле и привязан чат:

```bash
python manage.py senddigest                     # отправить
python manage.py senddigest --dry-run           # показать текст, ничего не отправляя
python manage.py senddigest --user admin        # только одному, для проверки
python manage.py senddigest --user admin --force  # повторить, игнорируя историю
python manage.py senddigest --status            # кому и когда уходило
```

`--status` отвечает на вопрос «сработало ли расписание»: показывает дату
последней сводки по каждому получателю. То же видно в разделе «Профиль»
блоком «Последние уведомления».

Всё это доступно и без консоли: раздел «Обслуживание» запускает те же режимы
кнопками, показывает вывод команды и историю отправленных уведомлений.

Повторов не будет: отправленное записывается в историю уведомлений. Сводка —
одна в день, предупреждение о лимите — одно на категорию в месяц. Недоставленное
сообщение в историю не попадает и уйдёт при следующем запуске.

Запуск по расписанию — cron (Linux), ежедневно в 21:00:

```
0 21 * * * cd /path/to/fincontrol && .venv/bin/python manage.py senddigest >> logs/digest.log 2>&1
```

На Windows то же делает «Планировщик заданий»: ежедневная задача, запускающая
`.venv\Scripts\python.exe manage.py senddigest` из каталога проекта.
